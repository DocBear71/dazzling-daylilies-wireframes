Page Annotations: Admin Plant Editor (Wireframe 11 of 17)

This is the form Jean uses to add new plants and edit existing ones. It is the most complex admin page in the system. Plain English throughout.

Breadcrumb and "View on Public Site" Link

The breadcrumb shows Dashboard › Plants › Acapulco Sunset so Jean always knows where she is. "View on public site" opens the customer-facing plant detail page in a new tab so Jean can verify how her changes look without leaving the editor.

Sticky Save Bar (the floating bar at the top)

Appears as soon as Jean makes any change to the form. It stays visible as she scrolls down the long page so she never has to scroll back to the top to save. Shows an "Unsaved changes" warning in amber. Has both Save Changes and Discard buttons. The Save Changes button in the page heading row does the same thing. Two paths to save, no path to lose work accidentally.

Decision needed: Should the browser warn Jean if she tries to navigate away with unsaved changes? A standard browser "Leave page?" dialog would prevent accidental data loss. This is easy to add with a small amount of JavaScript and is strongly recommended for a form this long.
Section: Basic Information

Plant Name, Plant Type, URL Slug, Price, Hybridizer, Year Introduced. The price field has a dollar sign prefix so Jean does not need to type it. Internally, prices are stored in cents (2800 for $28.00) but the editor displays and accepts dollars with decimals, converting automatically on save.

Business rule: Prices are stored in cents internally to avoid floating-point rounding errors. The editor converts between dollars (display) and cents (storage) transparently. Jean never sees or types cents.
URL Slug Field

The slug is auto-generated from the plant name when a new plant is created (e.g., "Acapulco Sunset" becomes "acapulco-sunset"). Jean can edit it manually if needed, but changing it after the plant is live will break any bookmarks customers have saved and will also break photo matching for files already uploaded using the old slug name. The "Regenerate" button resets it from the current name. A warning should appear if Jean tries to change the slug of a plant that already has orders or photos.

Business rule: The slug is the photo-matching key. Photos uploaded with filenames like "acapulco-sunset_1.jpg" attach to this plant automatically. Changing the slug after photos are uploaded means those photos will no longer match unless they are renamed and re-uploaded.
Section: Plant Attributes (the dropdowns)

Seven attribute fields, all dropdowns: Color, Bloom Size, Ploidy, Foliage, Bloom Time, Rebloomer, Fragrant, plus a free-text field for Scape Height in inches. All are optional except Plant Type. Dropdown values are fixed at launch based on Jean's catalog; if she needs new values added (a new color category, say), that requires a developer change to the seeder data. This is an acceptable limitation for a catalog this size.

Decision needed: Should Jean be able to add new dropdown options herself from the Settings page, or is a fixed list acceptable? A fixed list is simpler to build and sufficient for a catalog of 48 plants. A configurable list gives Jean more flexibility but adds Settings complexity. Worth discussing.
Section: Descriptions (three text areas)

Short Description appears on catalog cards and at the top of the detail page. Long Description appears only on the detail page below the attributes. Internal Notes are private and never shown to customers. The Internal Notes field has a yellow background to visually distinguish it and remind Jean it is private. Placeholder text suggests example use cases ("Only 3 fans left. Check before accepting more orders.").

Section: Coordinated With

A search-and-chip interface for selecting companion plants. Jean types a plant name, matching results appear below the search box, and she clicks one to add it as a chip. Existing selections appear as blue chips with an × to remove. This wireframe shows 5 coordinated plants selected for Acapulco Sunset. The relationship is one-directional: adding Strawberry Candy here does not automatically add Acapulco Sunset to Strawberry Candy's coordinated list. Jean must set both directions manually if she wants the pairing to show on both detail pages.

Decision needed (carried forward from Wireframe 03): Should coordinated relationships be bidirectional automatically? If Jean pairs Plant A with Plant B, should Plant B automatically show Plant A as a companion? Auto-bidirectional is more convenient for Jean. Manual is simpler to build and gives Jean more control over which pairings show on which pages.
Sidebar: Status Toggles (Active and In Stock)

Two independent toggles in the sidebar. Active controls whether the plant appears on the public catalog at all. In Stock controls whether the plant can be added to a cart. Both can be flipped here without saving the rest of the form. Alternatively, Jean can save the whole form. Either way, the change takes effect immediately on the public site once saved.

Sidebar: Photos Panel

Shows up to the first few photos attached to this plant as small squares. The first photo has a "Primary" badge: it is the one shown in catalog cards, the cart, the order sheet, and the order confirmation email. Jean can drag photos to reorder them, changing which is primary. The × button removes a photo. The + button opens the upload dialog for this specific plant. "Upload More Photos" is a secondary path to the same action.

Business rule: Reordering photos changes the primary photo immediately. The primary photo is snapshotted into the order_items table when an order is placed, so changing the primary photo after an order exists does not affect how that order's printed sheet looks.
Delete Zone (bottom of the form)

Deliberately placed at the very bottom, below all other content, and styled in red to signal danger. Clicking "Delete This Plant" triggers a confirmation dialog before anything is deleted. The deletion is a soft delete: the plant record is flagged as deleted but not removed from the database. It disappears from the public catalog immediately. Edward can recover it within 30 days if Jean deletes something by mistake. Past orders referencing the plant are completely unaffected.

Business rule: Soft deletes protect against accidental data loss. The deleted_at timestamp is set; the plant is excluded from all public queries. Order history retains the plant name and photo as a snapshot in the order_items table, so printed order sheets are never affected by plant deletions.
