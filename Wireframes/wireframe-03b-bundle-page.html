Page Annotations: Coordinated Bundle Page (Wireframe 03b — New)

This is a new page with no equivalent in the original wireframe set. It opens when a customer clicks "View Bundle Details" from the bundle panel on a Plant Detail page (Wireframe 03, revised). Plain English throughout.

URL and Navigation

This page lives at a URL like /daylilies/acapulco-sunset/bundle. The breadcrumb shows Home › Daylilies › Acapulco Sunset › Jean's Sunset Garden Collection. A "Back to Acapulco Sunset" link at the top and a reference in the sidebar both return the customer to the anchor plant's detail page. The bundle is always associated with one anchor plant; its URL derives from that plant's slug.

New page
Bundle Description (Jean's Voice)

The paragraph below the bundle title is Jean's own description of why these plants work together: bloom timing, color relationships, height. This is entered in the Admin Plant Editor (Wireframe 11, revised) as a bundle description field. Jean should write this in her own words. It is the primary piece of copy that makes the bundle feel curated rather than arbitrary.

Decision needed: Should the bundle description field in the admin be required, or optional with no text shown if Jean leaves it blank? A bundle with no description loses the editorial voice that justifies the purchase. Recommended: optional but strongly encouraged, with a placeholder prompt like "Tell customers why these plants go together."
Plant List with Full Details

Each plant in the bundle gets a full row: large photo, name (linked to its own detail page), key attributes, a one-sentence description, and the individual price with an "Included" label. This level of detail lets customers evaluate whether the set is right for their garden before committing. Plant names are links so a curious customer can read the full detail page and come back.

Pricing Summary Block

Lists each plant's individual price, totals them, shows the discount as a line item, and displays the final bundle price. This transparency builds trust: customers can see exactly what they are getting and exactly how much they are saving. The individual total recalculates automatically if Jean changes any plant's price; only the bundle price itself is set manually by Jean.

Jean-flagged: Discount type (fixed dollar vs. percentage) and price-setting method (Jean enters bundle price directly vs. Jean defines a discount rule). Both decisions affect how this summary block displays and how it is stored in the database.
"Add Bundle to Cart" Button (sticky sidebar)

The green button in the sidebar is the primary conversion action on this page. Clicking it adds all plants in the bundle to the cart as individual line items, each at the proportional bundle price. The cart then shows five separate rows, each at its allocated bundle price, summing to the bundle total. Shipping is calculated normally based on plant count (5 plants = $15 + $8 = $23 in the example).

Decision needed: How should the bundle price be split across individual line items in the cart? Option A: split proportionally by individual price (e.g., Acapulco Sunset represents 22.6% of $124 individual total, so it gets 22.6% of the $112 bundle price). Option B: each plant is shown at its full price with a single bundle discount line item in the cart. Option A is cleaner for order sheets and records. Option B is simpler to implement. Jean should decide based on how she wants the order sheet to look.
Shipping Note in Sidebar

A plain-text reminder that shipping is calculated normally at checkout based on plant count, not as a fixed bundle shipping rate. Five plants = $15 + ($2 x 4) = $23. This sets the right expectation before the customer clicks Add to Cart and sees the cart summary.

Stock Handling

If any plant in the bundle is sold out, the "Add Bundle to Cart" button should be disabled and a message should indicate which plant is unavailable. A bundle cannot be purchased if any component is out of stock. Jean should mark the bundle as inactive in the admin if she knows a plant will be unavailable for the season.

Decision needed: Should Jean be able to mark a bundle as inactive independently of its component plants? Or should the bundle automatically become inactive when any component is sold out? Automatic is safer but may surface bundles as unavailable during brief stock gaps. Manual gives Jean control but requires her to remember to re-activate bundles after restocking.
Mix-and-Match (flagged as Jean's decision)

The wireframe shows a fixed bundle: all five plants are predetermined by Jean and cannot be swapped by the customer. This is the simplest approach. If Jean later wants to allow customers to substitute one plant in a set, that requires a significantly more complex UI (a configurator) and is out of scope for the initial build. The fixed-bundle approach is the recommendation for launch.

Jean-flagged: Fixed bundle as designed (recommended) vs. mix-and-match configurator. Mix-and-match is a future feature, not a launch requirement.
