Page Annotations: Printable Order Sheet (Wireframe 16 of 17)

This page opens in a new browser tab when Jean clicks "Print Order Sheet" from the Admin Order Detail page. Only the white order sheet area prints. The Print button, back link, and these annotations are hidden when printing. Plain English throughout.

How This Page Works

Jean clicks "Print Order Sheet" from the Admin Order Detail page. A new browser tab opens showing this page. Jean clicks the "Print Order Sheet" button at the top, which triggers the browser's print dialog. She selects her printer and prints. The page uses CSS print media queries to hide everything outside the white order sheet when printing, so only the clean sheet goes to the printer. No PDF generation library is strictly required for this: the browser's built-in print-to-PDF capability handles it if Jean wants a PDF instead of paper.

Decision needed: Should the order sheet be generated as an HTML page (as shown here, using CSS print styles) or as a downloadable PDF file using a library like DomPDF? HTML with print CSS is simpler to build and maintain. DomPDF gives more precise layout control and produces a file Jean can save. Given that Jean's primary use is printing directly rather than archiving PDFs, HTML with print CSS is the recommendation for launch. DomPDF can be added later if Jean wants to save order sheets as files.
Sheet Header: Business Name and Order Number

Business name, city, and email address on the left. Order number, date, and a Paid badge on the right. This gives the sheet a professional letterhead appearance and makes the order number easy to find if Jean needs to reference it later. No logo placeholder is shown because Jean has not yet decided on a visual brand; a logo image can be added in the design phase.

Content needed: Jean's full return address (street address and ZIP code) for the "Shipped From" block. This is shown as a placeholder. It is also needed for the shipping label in Wireframe 17.
Addresses: Ship To and Shipped From

Both addresses are shown side by side at the top. Ship To shows the customer's full name, address, email, and phone. Shipped From shows Jean's business address. Both come from the order record and Jean's settings respectively. Jean can use this section to verify the shipping address before affixing the label.

Plants Table with Thumbnails

This is the feature Jean specifically requested, inspired by Deb's Daylilies. Each plant row shows a 56px square thumbnail pulled from the plant's primary photo, the plant name, key attributes, quantity, unit price, and line subtotal. The thumbnails make it easy for Jean to verify she is packing the right plants and in the right quantities without having to read every name carefully. This is a meaningful packing accuracy aid.

Business rule: Photo thumbnails on the order sheet are non-negotiable. This is an explicit contract requirement. The thumbnail shown is the snapshot stored in the order_items.plant_photo_path column at the time the order was placed, not the current primary photo. If Jean changes the primary photo later, existing order sheets are unaffected.
Totals Block

Subtotal, shipping, and total charged, right-aligned below the plant table. Matches what the customer saw at checkout and in their confirmation email. The "No balance due" note in the payment confirmation strip reassures both Jean and the customer that the order is fully paid.

Jean's Thank-You Note

A personal message from Jean that she includes with every shipment. The placeholder copy ends with "I appreciate you! — Jean" matching her actual sign-off. Jean should review and approve this text. It is the same voice as her confirmation email message, so both should be approved together. Her contact info appears on the right side of this section so customers can easily reach her.

Content needed: Jean to approve or rewrite the thank-you note. This is a customer-facing piece of her personal brand. Decision needed: Should the thank-you note text be editable from the admin Settings page, so Jean can update it seasonally without developer help? Given that she may want to add seasonal messages ("Happy spring planting season!") or references to specific plant types, making it editable in Settings would be a useful addition. Low development cost.
Care Reminder Strip

A compact care summary at the bottom of the sheet reminding customers to open the box promptly, soak the roots, and plant soon. This reduces "my plants looked dead when they arrived" support emails. Jean should review and approve the wording. This text could also be editable in Settings for the same reason as the thank-you note.

Paper Format and Print Settings

Designed for standard US letter paper (8.5 x 11 inches, portrait). Jean should set her browser print dialog to: Paper size: Letter, Orientation: Portrait, Margins: Default or Narrow. "Print headers and footers" in the browser should be unchecked to avoid the browser adding its own URL and date lines to the printed page. These instructions should appear in Jean's admin guide.

Multi-Page Orders

For orders with many plants, the sheet may span two pages. The CSS handles this gracefully: the header reprints on the second page and the table continues. Page breaks are avoided mid-row so a plant's thumbnail and name never split across pages. Jean should test with a large order (8 or more plants) during the build phase to confirm the layout holds.

Decision needed: Should very large orders (10 or more plants) condense the thumbnail size to fit on one page, or is two-page printing acceptable? One-page is tidier for packing; two-page is more readable. Jean's preference.
